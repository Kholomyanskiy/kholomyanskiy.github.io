1.0 // WHO IT'S FOR

Who it is for

For a company that knows what it wants to automate: there is a specification, a requirements document or a clear task. Integrations of CRM, email, messengers and internal systems, workflows, chains with AI. AI isn't required here: sometimes it's enough to connect existing tools correctly.

2.0 // HOW IT WORKS

How the work goes

  1. Free call. The task, the systems, the scope.
  2. Specification. If there isn't one, it is written to the ANSS standard. A client's existing requirements document is checked by the same rules: acceptance criteria, boundaries, rollback. Small gaps are closed within the project, large ones with a separate specification.
  3. Build and configuration. Strictly to the specification. A change of scope is agreed separately before work on it starts.
  4. Acceptance. The solution is checked against the criteria from the specification on the client's data.
  5. Launch and handover. The solution runs in the client's processes, documentation is handed over.
  6. Support. At the client's choice, monthly.
3.0 // WHAT STAYS

What remains

A working solution accepted against the acceptance criteria. The specification it was built to, and documentation: how it works, how to make changes, what to do if it fails. The contractor is responsible for the result against the acceptance criteria. Example: a mechanics' output bot for a car repair shop on eSowa.
